# 2026-07-28 — First Flow-D listing goes live; the preview is checked against it

The first product listed through the in-app attribute screen (Flow D) went live on Myntra, which
finally gave us something we had never had: a **published page to check the preview against**. The
owner supplied the exact workbook he uploaded (`templates/myntra/Prefilled from New feature.xlsx`,
2 rows), so every claim below is a comparison of a submitted row against its live page rather than
a reverse-engineering guess.

SKU `164SDE226RPPG` — *Rajasi Panna Green Golden Zari Pure Tissue Cotton Saree*, Myntra product

## What that settled

1. **"Border border" is Myntra's, definitively.** Our Border vocabulary contains no value with the
   word "Border" in it and `attribute_entry.validate_submitted` rejects anything that is not an
   exact vocab member, so we can only ever send one clean term. Myntra appends both words itself.
   Fixed by mirroring it (`37b3b9f`) so the preview matches reality instead of quietly tidying it.
2. **Design Details L1 names both colours**, metallics with a `-Toned` suffix. Implemented via
   `_colour_phrase` / `_colour_display`; the `-Toned` set is inferred from this one listing plus
   Myntra's site-wide colour naming, so it is a frozenset that is cheap to correct.
3. **The blouse suffix in `reconstruct_title` is wrong.** Everything else in the title matched word
   for word; only our appended "With Unstitched Blouse Piece" was spurious. The trigger must be the
   separate `Blouse` column (`Blouse Piece` / `Stitched Blouse` / `NA`), which `constants.yaml`
   pins to `NA` on every row — not `Blouse Fabric`. **Left unfixed**: the owner approved the L1
   change only.
4. **⚠️ Myntra can overwrite a submitted attribute.** A border sent as `Solid` was published as
   `Woven Design` in both the prose and the Specifications table. Myntra runs AI attribute
   extraction over the product images with catalogue-team review, and the saree visibly has a
   woven gold border. This bounds what any preview can promise: what we send is an input, not the
   final state of the listing.
5. **`Print or Pattern Type` vs `Pattern` is still unresolved** — both rows set the two columns to
   the same value, so neither discriminates which one feeds the title's leading word.

## Open: colour in the product title

The owner wants the colour in the title (he has a multi-coloured saree) after seeing a competitor
listing — *Olive Green Ethnic Motifs Zari Pure Cotton Saree*. That title is our exact formula plus a
leading colour, and Myntra's published title convention is *Style Descriptor → Design Detail →
Material → Product Type*, with sellers explicitly advised to keep colour out of titles. Three
hypotheses fit the two samples we have, and they disagree:

1. **`Type` displaces colour** — the competitor sets no `Type`; we set `Khadi`. Myntra weights the
   first 60 characters, so colour may lose a token budget. *Test: leave `Type` blank on one listing.*
2. **Colour appears only for colour-variant groups** (the template's `Color Variant GroupId`). If
   so, a single multi-coloured saree can never get it.
3. **`Brand Colour (Remarks)` drives it** — weakened: ours held `green` (lowercased, auto-derived)
   and no colour surfaced.

Owner is researching this himself; nothing to build until a hypothesis survives.

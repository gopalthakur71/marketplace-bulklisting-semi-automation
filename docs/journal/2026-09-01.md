# 2026-09-01 — Pick your SKUs, cap the list name, remove a photo (and take it back)

Three changes to the Preview & edit screen, specified in
[`docs/Marigold_Ops_Change_Handover.pdf`](../Marigold_Ops_Change_Handover.pdf) — the first spec
this project has taken as a PDF rather than a written-here design doc. Branch
`feat/preview-select-and-image-remove`.

The PDF left five open questions. Three were answerable from the code and were not put to Gopal:
the filtered export's filename convention (it suggested one), whether the value is trimmed on
export (`validate_freetext` strips, so the limit measures the trimmed string), and whether images
can be added beyond Additional 2 (`image_specs.yaml` sets `max_images: 7` and `IMAGE_COLUMNS` has
exactly seven, so "add" means filling an empty named slot). The other two changed what got built.

## What shipped

**Per-SKU selection and a filtered download.** A checkbox on each SKU row, an email-style
Select all with a real indeterminate state for a partial selection, and `⬇ Download selected (N)`
that appears only once something is ticked. `attribute_entry.write_subset()` copies the workbook
and deletes the unticked rows **bottom-up**, then re-applies `shared_to_inline`; the schema,
column order, live dropdowns and current edits are all identical to the full export (there are
tests for the header row and for an edit made after page load). Rows are deleted rather than
blanked because a blank row inside the data region is exactly what made the template's stray
example row fail an upload. Selection is resolved by SKU **read from the sheet**, not by the row
offsets the screen was rendered with, so a stale screen still exports what was ticked. Nothing
selected is a 400, and a selection that matches no row is a 409 — never a silently empty sheet.

**List View Name capped at 30.** Myntra rejects the whole SKU above 30 characters. The PDF asked
for the over-limit text to stay visible with an inline error; Gopal overrode that — *"30 character
is must, user can not put beyond 30 char"* — so the field carries `maxlength=30` and a live
`NN / 30` counter. Worth knowing: this means a **paste** of a longer name is silently cut to 30,
which is the corruption the PDF's author was trying to avoid. The over-limit error still exists,
because it has a case the keystroke cap cannot reach — a workbook **uploaded** through Preview can
already hold a 40-character name. `over_limit_freetext()` flags it red on load and
`validate_freetext` refuses to save it, so this screen cannot write a name Myntra would reject.

**Remove a photo, and undo it.** Every filled slot gets its own Remove. It shipped first as a
checkbox read by the "Upload new images" button, which Gopal immediately found broken-feeling —
ticking it did nothing visible — so it became a button that posts on its own click. It
`hx-include`s **only** the hidden SKU field: including the panel would re-post every file input
alongside the removal, turning one click into an upload of whatever else was chosen.

The removal is written **before** the uploads, so clearing a cell still works when the S3 leg
fails, and it wins over a file chosen for the same slot in the same click. The displaced URL is
stashed on `job.result["removed_images"]` and offered back as `↺ Undo` in the same spot; the undo
route takes **only** the ordinal and slot, never the URL, which is what stops it being a way to
write an arbitrary string into an image column. The entry is consumed on use and dies with the
process, like every other edit on this screen.

Sharing one partial (`_slot_actions.html`) between the panel and the out-of-band swaps fixed two
things that were wrong before: a photo uploaded into a previously empty slot now gains its Remove
without a reload, and the removal hint only names Undo when one is actually offered (a slot cleared
of a bare local basename has no URL to hand back, and the hint used to promise a button that was
not there).

## Deliberately not built

The PDF's §3.4 minimum of 3 images, its §4 cross-cutting "export-valid SKU" notion, the invalid-SKU
badge, and blocking invalid SKUs from download. Gopal's answer on the image minimum was *"keep the
available image slots. just give me option to remove the images if they are uploaded already"*, and
with a hard 30-character cap there is no over-length SKU left to block. A product can therefore now
be taken down to zero images, and Remove has no confirmation dialog.

## Review note

Self-review before merge caught one real deviation: the full **Download xlsx** had started naming
an uploaded job's file after the owner's own filename. The PDF says in as many words to keep that
fallback untouched, so it went back to `myntra_filled.xlsx` and the original-name stem is now used
only for the `_selected_<N>` export, which is where the PDF asked for it.

Two knowingly-accepted risks, both pre-existing patterns rather than new: the selected download
reads the workbook without taking `_WRITE_LOCK`, so a download racing a save could read a torn
file (single-owner app; the full download has always had the same exposure), and the filtered file
is rebuilt at a fixed per-job path on every request.

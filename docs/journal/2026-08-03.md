# 2026-08-03 — Stop and Clear on the Generate screen; HSN-from-Shopify designed, then parked

Two things were asked for together: sourcing HSN from a Shopify `custom.hsn` metafield instead of
the on-screen knowledge base, and a pair of buttons on the Generate screen. Only the second was
built. The first was designed in full, then deliberately deferred — the owner has a separate plan
for the metafield and wants the existing HSN flow left alone until then.

Spec: [`docs/superpowers/specs/2026-08-03-hsn-from-shopify-and-stop-clear-design.md`](../superpowers/specs/2026-08-03-hsn-from-shopify-and-stop-clear-design.md).
Branch `feat/generate-stop-clear`.

## Why HSN-from-Shopify was designed and then parked

Background from 2026-07-27: Shopify's product CSV export **does not contain the variant Shipping
tab's HS code at all**, which is why the HSN knowledge base exists. Product *metafields* do
export, so a `custom.hsn` product metafield closes the gap. That was confirmed to now exist in the
owner's export, and the design was written: read the column, hard-block any batch containing a
blank or non-8-digit code (naming the offending SKUs), take HSN from the product in the mapper,
and retire the on-screen review.

It is retained in the spec, clearly marked deferred, with one item still open — the exact export
header string, which Shopify derives from the metafield's name and must be read off a real export
before anything is built.

**One trap recorded there, because it would have failed silently.** `scan_content_hashes` — the
input to the duplicate-upload guard — deliberately hashes rows with HSN *unset*. If HSN began
flowing from the export into those cells, every SKU already in the registry would hash differently
and the next upload would report the whole catalogue as "edited". Whoever revives this must keep
the scan path HSN-free.

## What was built

**Stop.** A button beside Generate, present only while a build runs. It sets `cancel_requested` on
the job; `pipeline.main` takes a new `should_cancel` callable and checks it between whole products,
before `fill_template`, and before the S3 upload, then raises `BuildCancelled`.

Cancellation is cooperative on purpose. Killing the worker thread mid-write risks a corrupt
workbook and a half-uploaded image set, so a Stop lands within one product instead of instantly —
a wait of a second or two that buys a guarantee.

That guarantee is that a stopped run leaves **no trace**: the part-written `myntra_filled.xlsx` is
deleted, `groupid_ledger.cancel()` marks the reserved batch `cancelled`, and no SKUs are
registered. Two of those three came free from existing invariants — `reserve()` never advanced the
id counter, and `record()` only runs after `pipeline.main` returns — which is why the feature cost
so little. `cancelled` is a distinct job status from `error`; a deliberate stop is not a failure.

**Clear.** Resets the chosen CSV and empties the panel below the form. Per an explicit decision it
wipes a finished result and its download link too; the built file on disk is untouched.

## Two defects found reviewing my own work, before either reached the owner

**Stop would have re-uploaded the whole CSV on every click.** It sits inside the upload form, and
htmx posts an enclosing form's values by default — with `hx-encoding="multipart/form-data"`
inherited from the form, that means the file. Fixed with `hx-params="none"`, pinned by a test.
Worth remembering for any future control placed inside that form.

**The `.btn.secondary` class the design specified did not exist** in `app.css`. Stop and Clear
would have rendered as full marigold, competing with Generate for attention. Added.

## Placement note

The design first put Stop inside the progress panel; the owner had asked for it *next to Generate*.
It now lives in the form's button row, filled by an out-of-band swap that rides the stepper's
existing one-second poll. That poll makes the control self-healing — it is re-asserted every second
while running and withdrawn within a second of the run ending, so a single missed swap corrects
itself rather than stranding a dead Stop button on screen.
